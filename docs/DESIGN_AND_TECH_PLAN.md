## 1. 권장 스택 (한눈에)

| 영역 | 권장 | 이유 |
|------|------|------|
| 게임 엔진 | **Phaser 4 + TypeScript + Vite** (2026-09-30 정정: Phaser 4가 2026-04 정식 출시, 버전·근거는 `docs/TOOLING.md`) | 2D 스프라이트에 최적, 이미 설치된 Node/pnpm으로 즉시 시작, 핫리로드가 빠름 |
| 모바일 패키징 | **Capacitor** (iOS/Android 래핑) | 웹 게임을 그대로 앱으로. 음성 인식·푸시 등은 네이티브 플러그인 |
| 실시간 서버 | **Colyseus** (Node/TS) | 방(Room) 단위 7인 동기화가 기본 제공, 클라와 타입 공유 가능 |
| 배포·DB | **Railway** (서버 + Postgres) | Railway CLI·MCP가 이미 연결됨 |
| 영어 AI 대화 | **Claude Haiku 4.5** (`claude-haiku-4-5-20251001`) — 서버 프록시 경유 | 저렴·빠름. 키는 서버에만 둠 |
| 음성 | 발화 인식: **기기 내장 음성 인식(온디바이스)**, 안내 음성: **사전 생성 TTS 파일** | 아이 음성을 서버로 보내지 않음, 실시간 TTS 비용 0 |
| 맵/레벨 | **Tiled** | 충돌 영역·오브젝트 배치를 JSON으로 |
| 스프라이트 | 자체 **슬라이서/아틀라스 도구** + (선택) Aseprite/LibreSprite | 아래 §5 |

**대안 비교 (선택 근거)**
- *Godot 4*: 네이티브 내보내기·셰이더가 강점이지만, 별도 설치·GDScript 학습, 멀티/AI 연동을 전부 새로 붙여야 함. Node 생태계와 Claude Code 협업 효율은 Phaser 쪽이 높다.
- *Unity*: 7인 실시간·모바일에는 가장 성숙하나 2D 수채화 스프라이트 작은 게임에는 과함, 빌드·용량·라이선스 부담.
- **Phaser+Capacitor의 약점**: 웹뷰 성능(저사양 안드로이드), 큰 텍스처 메모리. → 아틀라스 2048 이하, 배경은 타일 분할로 대응 (§6).

## 2. 개발 환경 준비 체크리스트

이 Mac(M3 / 16GB / 여유 95GB) 기준. 현재 없는 것만 표기.

**필수**
- [ ] **Xcode** (App Store, 약 15GB+) → 설치 후 `sudo xcode-select -s /Applications/Xcode.app` 및 라이선스 동의, iOS 시뮬레이터 받기
- [ ] **Apple Developer Program** (연 $99) — TestFlight·출시에 필요. 실기기 테스트만이면 무료 계정도 가능(7일 서명 만료)
- [ ] **Android Studio + JDK 17** (`brew install --cask android-studio temurin@17`), 에뮬레이터 1개
- [ ] **Google Play Console** (일회성 $25)
- [ ] 저사양 **실기기** 안드로이드 1대 (성능 기준선)

**권장**
- [ ] Tiled (`brew install --cask tiled`)
- [ ] LibreSprite 또는 Aseprite (스프라이트 수정용, 선택)
- [ ] ImageMagick (`brew install imagemagick`) — 이미지 일괄 처리
- [ ] Docker — 서버를 로컬에서 Postgres와 함께 돌릴 때 (없으면 Railway 개발 환경으로 대체 가능)

**이미 있음**: Node 20, pnpm, bun, Python, ffmpeg, Railway CLI.

**저장소 구조 (pnpm workspace 모노레포)**
```
island/
  apps/client/       Phaser + Capacitor
  apps/server/       Colyseus + Postgres 접근
  packages/shared/   방 상태 스키마, 메시지 타입, 커리큘럼 타입
  tools/             sprite-slicer, atlas-pack, content-lint, tts-batch, bots
  content/           (기존) 원본 AI 이미지 — 수정하지 않고 보존
  assets/            가공된 스프라이트·배경·오디오
  data/              단어·대사·퀘스트 JSON/CSV
  docs/
```

## 3. 세계관과 등장인물

**공간 (고정 구역, 화면 단위로 나눔)**
1. **선착장** — 배가 오는 곳, 편지·손님·낚시
2. **꽃 들판** — 식물 재배, 곤충 채집 (섬 이미지 왼쪽)
3. **숲 그늘** — 희귀 곤충, 버섯·열매 (섬 이미지 오른쪽 어두운 초록)
4. **캠프** — 텐트, 게시판, 저널, 잔치 장소 (채집 장면 콘셉트)
5. (후속) 바닷가 / 언덕

배치(4×4 화면)와 크기 기준(타일 48px, 고양이 약 92px)은 `docs/ISLAND_LAYOUT.md`.

**캐릭터**
- **플레이어 7인**: 모두 고양이, 기본 시트 하나를 **팔레트 스왑**(털색·점 무늬색·스카프색)으로 7가지 외형 제공. 모자·가방 같은 소품은 레이어로 추가.
- **NPC 가이드**: 안경 쓴 회색 노인 고양이(퀘스트 게시판, "Professor"), 밀짚모자 새끼 고양이(수집가 친구), 선착장 낚시꾼, 요리사, 우체부 — 1차는 **3명**, 이후 추가.
- NPC마다 **말투 레벨과 주제 어휘**가 다르다 (수집가=동물/색, 요리사=음식/수량, 낚시꾼=날씨/시간).

## 4. 게임 진행 방식

### 4.1 하루 루프 (세션 8~15분)
```
아침  게시판에서 오늘의 섬 일 3개 확인 (영어 지시문 + 그림)
낮    혼자 활동: 채집 / 물주기 / 수확 / NPC 대화 (개인 농장은 내 것, 들판·숲은 공유)
오후  파티 활동: 친구 코드로 모여서 역할 분담 퀘스트
저녁  캠프 잔치: 모은 재료로 요리 → 영어로 주문/나눔 → 도감·스티커 보상
밤    식물이 자람(서버 시각 기준), 다음 날 손님 예고 편지
```
- 식물은 **실시간(또는 앱 종료 중 경과 시간)** 으로 자란다. 단, 시들지 않는다(벌점 금지). 오래 안 들어와도 "기다렸어!" 연출만.

### 4.2 핵심 활동
- **채집(곤충·물고기)**: ~~타이밍 링~~ → **게이지 바** 미니게임(2026-10-02 변경) — 왕복하는 마커가 초록 구간일 때 터치. 3번 놓치면 4번째에 곤충이 도망. 잡으면 도감 등록 + 영어 단어 카드(그림+소리). 수치·장비 효과·보상은 `REWARD_SYSTEM.md`.
- **재배**: 씨앗 요청(영어) → 심기 → 물주기 → 성장 단계 4~5단계 → 수확. 꽃 종류는 색 어휘와 연결(pink, blue, yellow, white).
- **도감(저널)**: 콘셉트의 "3/10" 저널. 종류별 수집 + 단어·예문·발음 재생. 복습 큐의 입구.
- **꾸미기**: 수확한 꽃·돌·통나무 배치 (고정 슬롯 방식).

### 4.3 7인 파티 (협동)
- **방**: 친구 코드 4~6자리로 입장하는 비공개 방, 최대 7명. 공개 매칭은 1차에서 제외(안전).
- **역할 카드** (매 퀘스트 배정): Gatherer(곤충) / Gardener(식물) / Fisher(물고기) / Cook / Explorer / Messenger / Helper.
- **정보 격차 퀘스트**: 각자 화면에 **다른 카드**만 보인다. 예) 요리사는 "파란 꽃 2개 필요", 정원사만 파란 꽃이 있다 →
  `Do you have a blue flower?` / `Yes, I do. Here you are.` — 문장을 **선택지 조합 또는 따라 말하기**로 전달해야 진행.
- **잔치**: 모두의 기여가 합쳐져야 완성 → 전원 보상. 경쟁 요소 없음.
- 7명이 안 모이면 **빈자리를 NPC가 채움** (혼자·2~3명도 플레이 가능해야 함).
- 채팅은 **문장 휠(정해진 영어 문장 + 이모티콘)** 만. 자유 입력 없음.

### 4.4 영어 학습 설계
- **레벨**: Pre-A1(단어·한 문장) → A1(간단한 질문·대답).
- **유닛(각 1~2주)**: ① Greetings & Names ② Animals & Insects ③ Colors & Flowers ④ Food & Numbers ⑤ Weather & Time ⑥ Places & Directions. 유닛당 단어 12 + 문장 패턴 3.
- **말하기 3단계(점진적)**:
  1. *듣고 고르기* — NPC 말을 듣고 그림 선택
  2. *문장 만들기* — 조각 카드를 끌어 문장 완성 후 말하기
  3. *자유 응답* — NPC와 AI 대화 (주제·어휘 고정된 범위 내)
- **피드백**: 정답/오답 대신 "거의 맞아요! 다시 한번 → *I like flowers.*" 같은 **재시도 힌트**. 문법 교정은 짧게, 한 번에 하나만.
- **복습**: Leitner 박스(1일→3일→7일→14일). 복습은 '도감 열기' 또는 NPC 심부름으로 위장.
- **발음**: 온디바이스 음성 인식 결과를 **관대하게** 채점(단어 일치율 기준, 임계값 낮게). 점수를 숫자로 보여주지 않고 별(1~3)로.

### 4.5 AI 대화 (Claude) 가드레일
- 클라이언트는 **서버 프록시**만 호출. API 키는 Railway 환경 변수에만 저장.
- 시스템 프롬프트로 고정: 캐릭터 설정, **어휘 제한(해당 유닛+이전 유닛)**, 답변 **12단어 이하**, 주제 이탈 시 퀘스트로 복귀, 개인정보 질문 금지·거절.
- 응답은 구조화(JSON): `{reply, hint_ko, words_used[], on_topic}` → 서버가 **허용 어휘 린트 + 안전 필터** 통과 못 하면 **사전 작성 대사로 대체**.
- **턴 상한**(세션당 N턴)과 캐싱으로 비용 제한. 오프라인/실패 시 스크립트 대사로 자연스럽게 폴백.
- 아이 입력 원문은 로그에 남기지 않거나 최소 보관 (보호자 동의 범위 내).

## 5. 그래픽·스프라이트 파이프라인

### 5.1 현재 자산 진단
| 자산 | 상태 | 해야 할 일 |
|------|------|-----------|
| 캐릭터 시트 | 4×3, **흰 배경(알파 없음)**, 칸마다 위치·크기 약간 다름 | 배경 제거 → 셀 분리 → **발바닥 기준 피벗 정렬** → 크기 통일 |
| 방향 | 정면 / 뒤 / **왼쪽 옆** | 오른쪽은 **좌우 반전**으로 생성 (옆모습이 있어 4방향 해결) |
| 동작 | 대기, 걷기 A/B, 포충망 | 걷기는 **대기-A-대기-B 4프레임 루프**로 재구성 |
| 추가 필요 | 물주기, 심기, 수확, 잡기 성공/실패, 말하기, 기쁨/놀람, 앉기/잠 | 새로 생성 (아래 workflow) |
| 섬 배경 | 한 장짜리 그림 | 걷는 영역 마스크(Tiled 폴리곤) + 깊이 정렬용 오브젝트(나무·텐트·말뚝)를 별도 스프라이트로 분리 |
| 채집 장면 | **UI 콘셉트 이미지** (실사용 자산 아님) | 저널·링·말풍선·시계를 각각 UI 아틀라스로 새로 제작 |

### 5.2 일관성 유지 방법
- AI로 캐릭터를 추가 생성할 땐 **Higgsfield `character-sheet` workflow**로 같은 캐릭터를 고정(기존 시트를 참조 입력). 칸 구성은 현재 시트와 **완전히 동일한 4×3 규격**으로 요청.
- 배경 제거는 `remove_background` 또는 로컬 `rembg`. 윤곽선(갈색 선)이 깎이지 않는지 확인.
- 7명 플레이어 외형은 **새로 그리지 않고 팔레트 스왑 셰이더/사전 변환**.
- AI 생성 이미지는 프레임 간 미세 흔들림이 생기므로 **모든 프레임 정렬은 도구가 자동 수행**하고, 사람이 눈으로 마지막 확인.

### 5.3 만들 도구 (tools/)
| 도구 | 기능 | 상태 |
|------|------|------|
| `sprite-slicer` | 알파 기준 연결 성분으로 셀 자동 분리 → 피벗 정렬 → 균일 캔버스 → 아틀라스 PNG + JSON(Phaser 형식) | ✅ `tools/sprite_slicer.py` |
| `atlas-preview` | 아틀라스 재생·검수(피벗선, 어니언 스킨, 바닥 스크롤) | ✅ `tools/atlas_preview.html` |
| `palette-swap` | 털색/점/스카프 영역 마스크로 N색 변형 일괄 생성 | ✅ `tools/palette_swap.py` |
| `content-lint` | 단어·대사·퀘스트 JSON 검증: 허용 어휘 초과, 12단어 초과, 번역 누락, 중복 id, 에셋 경로 | ✅ `tools/content_lint.py` (+ 테스트) |
| `tts-batch` | 단어·문장 CSV → 음성 파일 일괄 생성(기기 용량 고려해 mp3/ogg), 파일명 해시 | ⏸ TTS 제공자 미정 |
| `bots` | 7개의 가짜 클라이언트로 방 입장·이동·퀘스트 진행, 동기화/부하 테스트 | ⏸ 서버(M2) 이후 |
| `debug overlay` | 앱 내 FPS, 핑, 방 상태 JSON, 시간 빨리감기 (개발 빌드 한정) | ⏸ 클라이언트(M1) 이후 |
| `fx-lab` (신규 후보) | 채집 성공·성장·잔치 등 효과를 **파라미터 슬라이더로 조정**하고 프리셋 JSON으로 내보내는 Phaser 플레이그라운드 | ⏸ 클라이언트(M1) 이후 |

사용법은 `tools/README.md`. 현재 시트 기준 측정: 걷기 프레임의 머리 가로 흔들림 ≤ 4px(프레임 폭 238px의 약 1.7%), 포충망 프레임은 실루엣이 커서 몸통이 최대 7px 이동 — 육안 검수 대상.

**기성 도구 사용**: Tiled, TexturePacker 또는 `free-tex-packer-core`, Vite, Vitest, Playwright(웹 스모크), Colyseus Monitor.

**참고한 제작 사례 (2026-09-30 시청, 자동 생성 한국어 자막 기준)**
인디 게임 제작자의 Opus 5.5 사용 후기 영상에서 이 프로젝트에 적용할 만한 점:
- *효과(FX)·조명·날씨는 파라미터로 빼서 AI와 반복 개선*하는 방식이 잘 통했다고 한다 → 채집/성장/잔치 효과와 낮·밤·비 틸트는 **처음부터 파라미터 테이블**로 만들고 `fx-lab`으로 조정.
- 가장 어려운 문제로 **일관성 있는 캐릭터 스프라이트 애니메이션**과 **효과음**을 꼽았다 → 스프라이트는 자동 정렬 도구(위)로 흡수, **효과음은 AI 생성에 의존하지 말고** 라이선스가 명확한 음원을 골라 쓰는 쪽으로 계획(TTS와 별개 이슈).
- 방향별 스프라이트가 어려워 사이드뷰로 타협했다는 언급 → 우리는 이미 정면/뒤/옆 3방향 시트를 갖고 있어 출발점이 유리하지만, **동작 추가 생성(물주기·심기 등)은 같은 위험**이 있으므로 M1 전에 1~2개로 시험.

## 6. 이벤트·그래픽 효과 제안

**기술 기반**
- Phaser 파티클 + 트윈 + 카메라 이펙트 + (WebGL) 컬러 매트릭스 후처리.
- 전 화면에 아주 옅은 **종이 질감 오버레이**와 수채 번짐 전환(마스크 리빌)으로 그림책 느낌 유지.
- 텍스처: 아틀라스 2048 이하, 배경 2752×1536은 **1920 폭으로 줄이고 타일 분할** → 저사양 메모리 보호.

**상황별 효과**
| 순간 | 효과 |
|------|------|
| 걷기 | 발밑 작은 먼지/풀잎, 그림자 원형, 꼬리 살랑 |
| 채집 성공 | 링이 초록에서 반짝 → 포충망 스윙 → 스쿼시&스트레치 → 별 파티클 → 도감에 빨려 들어가는 카드 |
| 채집 실패 | 곤충이 "휙" 날아감 + 고양이 갸웃 (웃음 요소, 벌점 없음) |
| 씨앗 심기 | 흙 튀김, 싹 튀어나옴(탄성 이징) |
| 성장 단계 | 잎 파티클 + 종소리 |
| 수확 | 꽃잎 흩날림, 아이템이 포물선으로 가방으로 |
| 영어 발화 성공 | 말풍선이 스티커처럼 "쏙" 붙고 별 1~3개 |
| NPC 대화 | 말풍선 타자 효과 + 핵심 단어 하이라이트 + 탭하면 발음 |
| 파티 입장 | 배가 도착 → 선착장에서 한 명씩 내림 |
| 잔치 | 캠프파이어 불빛, 전원 모여 축하 컷, 색종이 |

**시간·날씨 이벤트** (섬 시계 기반, 학습 유닛과 연결 — 상세 규칙은 `WEATHER_AND_SPAWN.md`)
- 낮/노을/밤 컬러 틸트, 반딧불이(밤 한정 곤충)
- 비는 섬 일부에만 오고 옮겨 간다: 물웅덩이 반사, 지렁이·달팽이 출현(개구리는 관찰만) → Weather 유닛
- 바람: 꽃·풀 흔들림 셰이더 (vertex sway)
- 주간 이벤트: 병 편지(보물 지도/퀴즈), 철새 방문, 꽃 축제, 희귀 나비(저널 마지막 칸)

## 7. 멀티플레이 구조

- **서버 권위형**: 위치, 인벤토리, 작물 타이머, 퀘스트 진행은 서버가 확정. 클라이언트는 입력 전송 + 보간.
- **Room 타입**: `IslandRoom`(공유 구역, 최대 7), `FarmState`(개인 농장은 DB 저장).
- **동기화 주기**: 위치 10~15Hz + 클라 보간. 액션(잡기·심기)은 이벤트 메시지.
- **저장**: Postgres — 계정(보호자), 아이 프로필, 인벤토리, 도감, 복습 박스, 작물 타이머.
- **접속 끊김**: 재접속 시 같은 방 복귀, 7인 중 1명 이탈은 NPC가 자리 대행.
- **치트 방지**: 채집 판정 시각과 링 위치를 서버가 재계산(관대한 허용 오차).
- **Railway**: 서비스 2개(server, postgres). 개발/스테이징 환경 분리. 로그·지표는 개인정보 제거 후 저장.

## 8. 아동 안전·개인정보 (법무 검토 필수)

> 아래는 개발자 관점의 설계 요구이며 **법적 자문이 아니다.** 출시 전 전문가 확인 필요.

- **보호자 동의**: 한국은 만 14세 미만, 미국(COPPA)은 13세 미만 개인정보 수집에 법정대리인 동의 필요. 가입 흐름을 "보호자 계정 → 아이 프로필"로 설계.
- **최소 수집**: 아이는 닉네임(사전 제공 조합 닉네임 권장) + 학년대만. 실명·사진·위치·연락처 수집 없음.
- **채팅**: 자유 입력 없음, 문장 휠만. 신고/차단 버튼, 공개 매칭 없음.
- **음성**: 인식은 기기 내. 서버 전송·저장하지 않는 것을 기본값으로.
- **스토어 규정**: Apple Kids Category / Google Families 정책 — 서드파티 광고·분석 SDK 제한. 크래시 리포트 도구는 정책 부합 여부 확인 후 도입.
- **보호자 기능**: 플레이 시간 한도, 주간 학습 리포트(발화 횟수, 배운 단어), 데이터 삭제 요청.
- **AI**: 입력/출력 필터, 개인정보 질문 차단, 대화 원문 최소 보관.

## 9. 마일스톤 (1인 + Claude Code 협업 가정, 기간은 대략)

| 단계 | 산출물 | 완료 판정 | 대략 |
|------|--------|----------|------|
| **M0 준비** | 환경 설치, 모노레포, 스프라이트 슬라이서, 첫 애니메이션 캐릭터가 섬 위를 걸음 | 폰 시뮬레이터에서 캐릭터 4방향 걷기 | 1~2주 |
| **M1 싱글 버티컬 슬라이스** | 채집 미니게임 + 식물 1종 + 게시판 + NPC 1명 + 유닛 1(단어 12) + 도감 | 10분 "하루" 완주 | 3~4주 |
| **M2 2인 네트워크** | Colyseus 방, 위치 동기화, 친구 코드, Railway 배포 | 폰 2대 동시 접속 | 2~3주 |
| **M3 7인 파티** | 역할 카드, 정보 격차 퀘스트, 문장 휠, NPC 대행, 잔치 | 봇 7 + 실기기 2로 완주 | 3~4주 |
| **M4 영어 강화** | 음성 인식, TTS 자산, 복습 큐, AI 대화 프록시+가드레일 | 유닛 1~2 전체 학습 경로 | 3~4주 |
| **M5 안전·출시 준비** | 보호자 동의 흐름, 시간 한도, 리포트, 성능 최적화, TestFlight/내부 테스트 | 아이 5~10명 클로즈드 테스트 | 3~4주 |
| **M6 출시** | 스토어 심사 대응, 모니터링 | 공개 | 2주+ |

**주의**: 합계 약 4~6개월 이상. 가장 큰 불확실성은 (1) 스프라이트 추가 생성의 일관성, (2) 스토어 아동 정책 심사, (3) 저사양 안드로이드 성능. **M1까지는 네트워크 없이 만들되, 상태 구조는 서버 권위형(M2 이식 가능)으로 처음부터 나눈다.**

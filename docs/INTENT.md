# Island — 의도 문서 (Intent)

> 이 문서는 "무엇을, 왜, 누구를 위해, 어디까지" 만드는지를 고정한다.
> 구현 방법은 `DESIGN_AND_TECH_PLAN.md`에 있다. 두 문서가 충돌하면 이 문서가 우선한다.
> 작성일: 2026-09-30 · 상태: 초안 v0.1 (사용자 승인 대기)

## 1. 한 줄 요약

고양이 주민들이 사는 작은 섬에서 **동물(곤충·물고기) 채집과 식물 재배**를 하고,
**최대 7명이 실시간으로 파티**를 맺어 함께 섬 일을 해결하며,
그 과정에서 **영어 회화를 "게임 동작"처럼 자연스럽게 쓰게 되는** 초등학생용 모바일 게임.

## 2. 왜 만드는가

- 초등 영어 학습 앱은 대부분 "문제 풀이 + 보상 스티커" 구조라 **말할 이유**가 없다.
- 아이들이 오래 하는 게임(채집·농사·꾸미기 장르)은 **영어를 쓸 이유가 없다**.
- 이 둘을 붙이면: 영어가 "시험 과목"이 아니라 **친구에게 물건을 요청하고, 길을 묻고, 요리를 주문하는 도구**가 된다.
- 이미 확보한 자산(귀여운 수채화풍 고양이 캐릭터 시트, 섬 배경, 채집 장면 콘셉트)이 세계관과 톤을 정해 주었다.

## 3. 대상 사용자

| 구분 | 내용 |
|------|------|
| 주 플레이어 | **초등학생 7~12세** (한국어 화자, 영어 Pre-A1 ~ A1 수준) |
| 구매·승인자 | 보호자 (가입 동의, 시간 관리, 학습 리포트 수신) |
| 나중에 확장 | 학원·공부방 교사 (학급 코드로 같은 섬에 모이기) |

## 4. 플레이어에게 약속하는 경험

1. **"내 섬이 있다"** — 매일 들어오면 식물이 자라 있고, 새 손님이 와 있다.
2. **"친구랑 같이 한다"** — 친구 코드로 모여서 역할을 나눠 일하고 저녁에 잔치를 연다.
3. **"영어가 나를 도와준다"** — 영어로 말하면 일이 진행된다. 틀려도 벌점이 없고, NPC가 다시 알려준다.
4. **"보고 있으면 기분이 좋다"** — 수채화 질감, 부드러운 움직임, 작은 반응 효과가 풍부하다.

## 5. 확정된 결정 (사용자 답변, 2026-09-30)

| 주제 | 결정 | 영향 |
|------|------|------|
| 파티 형태 | **실시간 온라인 멀티, 최대 7인** | 서버 권위형 실시간 서버가 처음부터 필요 |
| 플랫폼 | **모바일 앱 우선 (iOS/Android)** | 터치 UI, 스토어 심사, Xcode·Android Studio 필요 |
| 영어 회화 | **혼합형** — 핵심은 대본(선택지+따라 말하기), 자유 대화는 AI(Claude) | 커리큘럼 콘텐츠 + AI 대화 프록시 둘 다 필요 |
| 대상 | **초등학생 (7~12세)** | 아동 개인정보·채팅 안전이 **최우선 제약** |

## 6. 성공 기준 (측정 가능해야 함)

**재미**
- 첫 세션(10분) 안에 채집 1회 + 식물 심기 1회 + NPC 대화 1회를 완료한다.
- 테스트 아이들 중 70% 이상이 "내일 또 하겠다"고 답한다.
- 권장 세션 길이 8~15분, 하루 1~2세션.

**학습**
- 4주 플레이 후 해당 유닛 단어 12개 × 4유닛 중 70% 이상을 이해 테스트에서 맞힌다 (사전·사후 테스트).
- 플레이어가 영어 문장을 **소리 내어 말하거나 선택해 말한 횟수**를 로그로 센다 (문제 정답률보다 '발화량'을 핵심 지표로).

**기술**
- 중간급 모바일 기기에서 60fps(최소 30fps), 7인 같은 방에서 지연 체감 없음(왕복 < 150ms 목표).
- 첫 실행 → 플레이 시작까지 30초 이내.

**안전**
- 플레이어 간 **자유 텍스트 채팅은 없다.** (정해진 문장·이모티콘만)
- 보호자 동의 없이 개인정보를 수집하지 않는다.

## 7. 비목표 (이번에 하지 않는 것)

- 플레이어 간 자유 텍스트/음성 채팅
- 광고, 인앱 결제의 랜덤 뽑기(가챠), 타임어택식 중독 설계
- 전투·경쟁·순위 중심 구조 (협동만)
- 성인·청소년 대상 고급 문법 교육
- PC/콘솔 출시 (구조상 웹 빌드는 가능하지만 목표 아님)
- 1차 출시에서 섬 전체 자유 건축 (고정 구역 + 배치 꾸미기 정도로 한정)

## 8. 설계 원칙 (판단이 갈릴 때 쓰는 기준)

1. **놀이가 먼저, 영어는 놀이의 동사.** 영어 때문에 게임이 멈추면 안 된다. 영어는 "요청하기·묻기·주문하기"라는 게임 행동이다.
2. **틀려도 괜찮다.** 벌점·생명·실패 화면 없음. 틀리면 NPC가 힌트 주고 재시도.
3. **아이의 안전은 기능보다 앞선다.** 안전 장치 때문에 기능이 줄어도 안전을 택한다.
4. **서버가 진실.** 멀티 상태(아이템, 작물, 파티)는 서버가 결정한다. 클라이언트는 표시만.
5. **콘텐츠는 데이터.** 대사·단어·퀘스트는 코드가 아니라 JSON/CSV로 만들고 검증 도구를 통과해야 배포된다.
6. **작게 끝까지.** 기능을 넓히기 전에 "10분짜리 완성된 하루" 하나를 먼저 만든다.

## 9. 제약과 현재 상태

- **개발 머신**: Apple M3, 16GB RAM, 여유 디스크 ~95GB. macOS.
- **설치됨**: Node 20, npm 10, pnpm 10, bun 1.3, Python 3.14, ffmpeg, Railway CLI.
- **미설치**: Xcode(명령줄 도구만 있음), Android Studio/JDK, Godot, Tiled, Aseprite, ImageMagick, Docker.
- **보유 자산** (`content/`, 모두 2752×1536 PNG, AI 생성):
  - 캐릭터 시트: 고양이 4열×3행 (정면/뒤/옆 × 대기·걷기 A·걷기 B·포충망 동작). 흰 배경(알파 없음).
  - 섬 배경: 수채화풍 원형 섬, 길, 선착장.
  - 채집 장면 콘셉트: 저널(3/10), 타이밍 링, 게시판 노인 고양이, 모자 쓴 새끼 고양이, 텐트.
- **예산·인력**: 미정 (질문 §10 참조). 1인 개발 + Claude Code 협업을 가정하고 계획을 짠다.

## 10. 열린 질문 (답에 따라 계획이 바뀜)

1. 출시 지역은? (한국 전용 vs 글로벌) → 아동 개인정보 법규 범위가 달라짐
2. 수익 모델은? (유료 1회 / 월 구독 / 학원 라이선스) → AI 대화 비용 한도 결정
3. 사용자 인증 방식은? (보호자 이메일 계정 + 아이 프로필이 기본 가정)
4. 교육과정 정합: 초등 영어 교육과정 필수 어휘를 기준으로 할지, 자체 커리큘럼으로 갈지
5. 스토어 출시 목표 시점과 베타 테스터(아이) 모집 경로
